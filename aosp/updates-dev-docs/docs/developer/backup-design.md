# עיצוב גיבוי ושחזור (סעיפים 923, 924, 925, 926, 927, 928, 955, 935)

סטטוס: עיצוב. אין FutureBackup. ה-overlay (`futureos_backup.mk`) מפעיל רק את התשתית של הפריימוורק.

## מה קיים בלי לכתוב קוד
| רכיב | מקור | מה הוא נותן |
|---|---|---|
| BackupManagerService | framework | הפעלה/כיבוי, תזמון גיבוי, שחזור |
| SettingsBackupAgent | SettingsProvider | **גיבוי הגדרות המערכת (955)**: Wi-Fi, שפה, בהירות ועוד, לפי ה-transport |
| `allowBackup` + כללים (`apps-template`) | כל אפליקציה | גיבוי נתוני אפליקציה (SharedPreferences, DB) |
| LocalTransport | AOSP | לבדיקות בלבד. לא למשתמש קצה (נשמר ב-`/data`, נמחק באיפוס) |

## מה חסר: transport
בלי GMS אין transport. נדרשת אפליקציית מערכת **FutureBackup** שממשת `BackupTransport` ורושמת את עצמה. עיצוב מוצע:

| יעד | סעיף | הערה |
|---|---|---|
| כרטיס SD / USB OTG | 926 | הדרך העיקרית. כתיבה דרך Storage Access Framework או `StorageVolume`. קובץ מוצפן עם סיסמת המשתמש (לא הסיסמה של הנעילה) |
| ענן | 925 | **לא בתכנון הנוכחי.** מותנה בהחלטה: דורש שרת, הסכמה מפורשת (503) והצפנה מקצה לקצה. עד אז אין |

## התנהגות
- **אוטומטי (923):** גיבוי הגדרות ונתוני אפליקציות פעם ביום כשהמכשיר טעון וכרטיס מחובר; אחרת תזכורת בהתראות. בלי כרטיס, אין גיבוי (שקוף למשתמש).
- **מצטבר (924):** גיבוי מלא של Android אינו מצטבר. שכבת FutureBackup שומרת רק קבצים ששונו מאז הגיבוי האחרון (לפי mtime + hash) ל-`/backup/<date>/`, עם מלא פעם בשבוע.
- **שחזור קובץ בודד (927):** הגיבוי של קבצי המשתמש (תמונות, מסמכים) נשמר כקבצים רגילים בכרטיס, כך שאפשר להעתיק קובץ אחד בלי כלי מיוחד. גיבוי הגדרות ונתוני אפליקציות הוא אטום ושוחזור רק במלואו.
- **שחזור מערכת מלא (928):** ר' `reliability-recovery.md`. אחרי התקנה מחדש, אשף ההפעלה הראשונה מציע שחזור מהכרטיס.
- **לפני OTA (935):** FutureUpdater קורא ל-`BackupManager.dataChanged()` / גיבוי הגדרות אם יש כרטיס.

## מה נשאר
1. לכתוב FutureBackup (אפליקציה חדשה, מחוץ לתחום של מסמך זה).
2. החלטה על ענן (925).
3. לבדוק שמפתחות Keystore לא מגובים (הכללים ב-`apps-template`).
