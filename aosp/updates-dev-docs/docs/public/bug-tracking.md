# מעקב באגים פומבי (סעיף 995)

## מצב
משוב ממכשירים עובר לריפו **פרטי** (`FutureOS-feedback`), כי הוא מכיל לוגים של משתמשים (update-feedback-design סעיף 5). לכן ה-issues הפנימיים אינם פומביים.

## הצעה: שני ערוצים
| ערוץ | נראות | מה בפנים |
|---|---|---|
| ריפו פרטי | פרטי | משוב גולמי, לוגים, מיון אוטומטי |
| GitHub Issues בריפו הציבורי (`FutureOS-`) | פומבי | באג מסוכם ומנוקה (בלי לוג, בלי מזהים) + פריט ב-`KNOWN_ISSUES.md` |

## כללים
1. רק בעל הפרויקט מעביר פריט מהפרטי לציבורי, אחרי הסרת מידע אישי.
2. כל פריט ציבורי כולל: גרסה, מכשיר, צעדי שחזור, חומרה, סטטוס.
3. באג אבטחה לא נפתח כ-issue ציבורי. כתובת קשר לדיווח אחראי: **[להגדיר]**.

## נשאר ידני
יצירת labels ותבנית issue בריפו, והחלטה אם הריפו הציבורי נשאר ציבורי (תלוי ברישוי, ר' `open-source-and-license.md`).
